# LMPT2 SSCS update — 19 Sep 2026

This update adds the six requested pilot-test changes.

## Changes

1. **Berthing Energy / Displacement**
   - The displacement value is now automatically linked from **General Information → Ship Major Dimensions → Displacement**.
   - The Berthing Energy displacement cell is read-only and displays the linked value.

2. **Cargo Management**
   - Cargo Pump / Spray Pump / Emergency Cargo Pump **Fill Rate** fields accept free text (no numeric spinner).
   - High Duty Compressor **Rate** accepts free text.
   - Gas Management System **Time to Start** and **Time to Stop** accept free text.

3. **Unloading Arm**
   - **Maximum Flowrate** and **Maximum Manifold Pressure** accept free text (no numeric spinner).

4. **Utility System**
   - Nitrogen Service and Fresh Water now each have two checkbox choices: **Available** / **Not Available**.
   - The two choices are mutually exclusive.

5. **User approval email**
   - When an admin approves a pending user, the approved user receives an EmailJS notification.
   - Approval itself remains successful even if the notification email fails; the admin is shown a warning instead.

6. **Vessel photo attachment**
   - New **Attachment** tab in each SSCS study.
   - Supports image uploads to the existing private `sscs-documents` Supabase Storage bucket.
   - Photo metadata is stored in the existing `documents` table and attachment state in `study_sections` (`section_key = 'attachments'`).
   - After the study is submitted, attached vessel photos are displayed in **SSCS Summary**.

## Database migration

No SQL migration is required for this update. The existing `study_sections`, `documents`, Storage bucket and RLS policies already support the new attachment section/document type.

## Local update / deploy

After replacing the modified files in your current project:

```bat
npm run build
npm run preview
```

Then commit and push:

```bat
git add .
git status
git commit -m "Add pilot feedback improvements"
git push
```

Vercel will deploy the new commit automatically. The Production URL stays the same.

Your `.env.local` is not included in the update package and should remain on your machine. No new environment variable is required by this update.
